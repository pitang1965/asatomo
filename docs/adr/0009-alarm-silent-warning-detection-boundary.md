# ADR-0009: アラーム無音警告の検知境界 — 音量0のみ・警告優先・強制しない

- ステータス: Accepted
- 日付: 2026-07-24

## 背景（Context）

[[スマホアプリ]]（Android）の目覚ましは、止める操作（「起きました」）が [[生存シグナル]]（アラーム停止）になる、本アプリの日常の核である。ゆえに「アラームが鳴らない」は単なる寝坊ではなく、その日の生存シグナルが一本立たないことを意味し、放置すれば無応答として[[死亡認定]]の入口（エスカレーション）に触れうる。端末の設定次第で目覚ましが実質機能しない状況を、本人に事前に知らせたい。

ここで実装事実が素朴な直感を覆す。アラーム音は `AudioManager` の**アラーム音量ストリーム（`STREAM_ALARM` / `USAGE_ALARM`）**で鳴らしている（[AlarmReceiver.kt](../../android/app/src/main/java/com/asatomo/app/AlarmReceiver.kt)）。このストリームは着信音ストリームから独立しており:

- **マナー/サイレント着信・着信バイブ**は着信ストリームを変えるだけで、アラームは**鳴る**。
- 実際にアラームを黙らせるのは **(a) アラーム音量が0（ミュート）**、**(b) DNDがアラームを遮断する設定**の2経路。
- (b) を「私のアラームを実際に遮断するか」まで確実に判定するには、通知ポリシーの読み取り権限（`ACCESS_NOTIFICATION_POLICY`）が要る。

論点は「**何を無音と見なして警告するか（検知境界）**」と「**警告に留めるか、鳴ることまで保証するか**」である。利用者は高齢の単身者が中心で、権限プロンプトの増加も、信用できない誤報も、ともに高くつく。

## 決定（Decision）

1. **誤報ゼロを最優先する。** 「実際には鳴るのに警告する」偽陽性は、本人にこの警告を無視することを学習させ、本当に無音の日に効かなくする。網羅より正確さを採る。

2. **検知対象はアラーム音量（`STREAM_ALARM`）＝0（ミュート）のみ。** `AudioManager.getStreamVolume` で**権限ゼロ**に読める、最も頻度が高く判定が明快な失敗経路だけを扱う。

3. **除外するもの（意図的に警告しない）:**
   - **マナー/サイレント着信・着信バイブ** — `USAGE_ALARM` に無関係で鳴る。警告すれば嘘になる。
   - **「音量が小さいが0でない」** — 音は出る。聞こえる/起きられるかは本人の聴力・環境しだいでアプリには判定不能。線引きが恣意的で偽陽性を生む。
   - **DND** — 権限（`ACCESS_NOTIFICATION_POLICY`）を要し、権限なしの中途半端な検知は「DNDだが実は鳴る」偽陽性を生む。実ユーザーの実害が確認されたらフェーズ2で足す。

4. **警告のみ。発火時の強制はしない（姿勢A）。** 鳴る瞬間にアラーム音量を自動で持ち上げる介入は採らない。本人が意図的に0にした音量（入院・同室者など）を黙って全開にするのは、本人側を「ただの目覚まし時計」に見せCONTROLを残す本人UX（CONTEXT.md 近況）と、[[旅行モード]]で確立した「沈黙を情報に変える／本人にコントロールを残す」思想への裏切りになる。

5. **提示は本人の明示操作を要する。** 警告は「⏰ 毎日の目覚まし」カードにインライン表示し、アプリ前面復帰（`onResume`）ごと＋アラームセット直後にチェックする。直し方は**ワンタップで音量を適正値へ上げ、同時にシステムの音量スライダーを見せる**（`FLAG_SHOW_UI`）。これは決定4が却下した「発火時の黙った自動介入」とは別で、本人が警告を見て自分の意思で押す透明な操作。`setStreamVolume` が弾かれた場合はサウンド設定へフォールバックする。

6. **文言は道具の不調として平易に。** 「見守ってくれる人に届かない」等の監視感・不安、技術語（STREAM_ALARM 等）、および誤りである「マナーモードを解除」は書かない。見守り者の有無で分岐しない（鳴らないという事実は同じ）。

## 結果（Consequences）

**正**

- 権限ゼロ・偽陽性ゼロで、最頻の失敗経路（音量0）を確実に押さえる。警告の信頼が保たれ、本当に無音の日に効く。
- 本人にコントロールを残す姿勢が、旅行モード・近況の本人UX思想と一貫する。
- ワンタップ修正で高齢者の「設定のどこかを探せ」脱落を避ける。

**負 / 要フォロー**

- **前面時しか捕まえられない。** 姿勢A（強制しない）の当然の帰結として、「夜に音量を0にしてアプリを閉じた」ケースは事前に検知できない。強制しない以上、鳴る瞬間の手当てはしないと決めた対価。
- **アラーム音量が最小1で止まる機種**では音量0警告が発火せず、その端末の真の無音経路はDNDのみになる。ただしその機種でも音量1で（か細くとも）鳴るため、決定3の「小さいは警告しない」と一貫し、実害は限定的。
- **DND遮断の穴が残る。** 権限コストとの引き換えで保留。フェーズ2の候補。

**将来の別線（本ADRの対象外）**

- **DND対応（フェーズ2）** — 実ユーザーの実害が確認され、`ACCESS_NOTIFICATION_POLICY` の対価が正当化できるとき。
- **生存確認が取れない時の強制鳴動** — 発火時に「沈黙が異常」をサーバ側の検知から知った上でのエスカレーション（[[死亡認定]]の手前の安全網。[ADR-0001](0001-death-certification-authorization-model.md) 系）。本人の生存状態をサーバから受け取って初めて成立する別機能であり、本ADRの静的な設定警告とは依存関係が異なる。

## 実測と再確認（grill 2026-07-24）

実機（開発端末）で検証し、決定4・5の「結果」で抽象的に挙げた限界が**この端末では現実の主問題**だと判明した。決定そのものは変えないが、前提の実測を記録する。

- **アラームストリームに下限があり、音量0に到達できない。** `dumpsys audio` で `STREAM_ALARM: Min:1（権限なしでは3）/ Max:7`。`settings put system volume_alarm 0` を書いても、`getStreamVolume` 相当の実値（`streamVolume`）は下限側に留まり0にならない。UIスライダーでは実質3/7未満に下げられない。
- **OSは音量0でもアラームを（か細く）鳴らす。** OS標準タイマーを「音量0」で発火させても小さく鳴った。つまり**この端末では、音量設定だけでアラームを完全な無音にはできない**。中心の恐れ（設定ミスで無音）は Android の下限保証が既に潰している。
- **帰結: 本ADRの音量0警告は、下限を強制するこの種の端末では発火しない（守る対象が存在しない）。** コードは正しく、信号（音量==0）が実機に届かないだけ。この端末で警告が出ないのは正常であってバグではない。

**再確認した判断（変更なし）:**

- **音量0判定は残す。** 無害・実装済みで、下限を持たない別機種やサードパーティ製ミュートアプリで実際に0にする利用者（一定数いる）には効く保険。この端末で出ないことは受け入れる。
- **DNDは保留のまま（決定3の格上げはしない）。** 下限を強制する端末での唯一の真の無音経路はDNDだが、それは利用者が自分でDNDを「完全な無音」に設定するという、高齢の対象利用者には起こりにくい能動操作を前提とする。そのために `ACCESS_NOTIFICATION_POLICY` を高齢者に積む対価は、守れる確率×実害に見合わない。**実ユーザーが実際にDNDで無音化された事例が出たら、フェーズ2で再検討する。**

## 追記: DND中の音量0偽陽性とその抑止（2026-07-26）

grill 2026-07-24 で「この端末は `STREAM_ALARM` に下限があり音量0に到達できないので、音量0警告は発火しない」と記録した。ところが実利用で、その同じ端末で**おやすみモード（DND）中に音量0警告が出た**。本人の設定音量は0ではなく、復旧ボタン（決定5）を押しても何も起きなかった。

**原因:** DND中は端末が `getStreamVolume(STREAM_ALARM)` を、下限保証（Min:1）を無視して**0として返す**。つまり決定3で「検知しない」と決めたはずのDNDを、実装が `getStreamVolume==0` 経由で**間接的に拾って偽陽性化**していた。復旧ボタンが無反応なのは、真因がDNDで `setStreamVolume` が効かず、`onResume` の再判定でまた0に戻るため（見た目が変わらない＝「何も起きない」）。

これは決定1（誤報ゼロ）に真っ向から反する。前面復帰のたびに信頼できない警告を出し、本人に無視を学習させる——決定1が最も恐れた失敗そのもの。

**決定の精緻化（方針は不変）:** `isMuted()` は**DND中は false を返す**（音量0警告を出さない）。DND状態は `NotificationManager.currentInterruptionFilter` の**読み取りのみ**で判定し、`ACCESS_NOTIFICATION_POLICY` は要らない（設定変更はしないため）。`INTERRUPTION_FILTER_ALL`（DND off）以外を「DND中」とみなす。

- これは決定3の「DNDは扱わない」の**格上げではない**。DNDを「検知して警告する」対象にはしていない（フェーズ2のまま）。「DND中は音量判定を信用しない」という**除外条件**を明文化しただけで、権限も増えない。
- 実害がないことの根拠: アラームは `USAGE_ALARM` でDNDを貫通して鳴る（[AlarmReceiver.kt](../../android/app/src/main/java/com/asatomo/app/AlarmReceiver.kt)）。唯一アラームまで止める `INTERRUPTION_FILTER_NONE`（完全サイレント）は、利用者が自分でDNDをそう設定する能動操作が前提で、grill 2026-07-24 の判断どおりフェーズ2の範囲。
- 実装: [AlarmAudio.kt](../../android/app/src/main/java/com/asatomo/app/AlarmAudio.kt) `isMuted()` 冒頭で `isDndActive()` ガード。

## 検討した代替案（Alternatives considered）

- **姿勢B/C（発火時に音量を強制的に上げて必ず鳴らす）**: 本人が直し忘れても命綱が切れない利点はあるが、意図的な無音を黙って覆すのは本人UX・透明性思想への裏切り。要望も「警告」であり却下。強制は将来の「生存確認が取れない時」に限定した別線として残す。
- **DNDも初版から検知**: 命綱の穴は塞がるが、高齢者に重い権限プロンプトを1枚増やし、権限なしでは偽陽性を生む。費用対効果が合わず却下（フェーズ2へ）。
- **「音量が小さい」も警告**: 聴力の弱い利用者への配慮になるが、閾値が恣意的で、決定1の誤報ゼロ原則に反する。却下。
- **起動時モーダルダイアログで警告**: 目立つが、高齢者は反射的に閉じて学習効果が低く、うるさい。インライン＋カード内完結を採用し却下。
