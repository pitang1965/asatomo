# ADR-0010: 見守りWeb を PWA 化する — インストール可能・オフライン非対応（network-only）

- ステータス: Accepted
- 日付: 2026-07-25

## 背景（Context）

[[見守りWeb]] は [[見守り者]]の完全な面であり、まれで重いフロー（[[死亡認定]]・[[最後の伝言]]の開示/復号・[[招待]]の `/join` 承諾）の唯一の実装でもある（[ADR-0006](0006-platform-seam-frequency.md)）。iPhone [[本人]]・純Web [[見守り者]]にとっては**日常の入口そのもの**だが、ログイン後はブラウザのタブでしか開けず、ホーム画面から一発で戻る手段がなかった。ワンタップ復帰を与えるため PWA 化する。

問題は「**どこまでの PWA にするか**」である。PWA には (X) インストール可能まで（manifest＋最小 SW、中身は毎回ネットワーク）と、(Y) オフライン動作まで（SW がシェル・データをキャッシュ）の2段階があり、必要な実装の重さと**安全性のリスク**が全く違う。見守りWeb は生死に関わる安全網であり、キャッシュの扱いを誤ると単なる不便では済まない。

## 決定（Decision）

**(X) インストール可能までとし、オフラインのデータキャッシュはしない（network-only）。**

1. **manifest を出し、インストール可能にする。** `name`/`short_name` = 「アサトモWeb」（[ADR-0008 §改訂](0008-watch-web-bottom-nav-direction-split.md)）、`start_url` = `/me`、`display` = standalone、`scope` = `/`、`lang` = ja。`theme_color`/`background_color` はヘッダー背景 `#f4f7fb` に合わせ、dark は `<meta name="theme-color" media="(prefers-color-scheme: dark)">` で `#14171f` に上書き。

2. **サービスワーカーは「インストール要件を満たすための最小実装」に限定する。** fetch は素通し（network-first / passthrough）。**[[近況]]・認証済みページ・危険フローを SW でキャッシュしない。** オフライン時は素直に「接続が必要」を見せる。

3. **アイコンはネイティブ目覚ましと同一意匠**（`sun-heart`）を 192/512/maskable に書き出す。ホーム画面での区別はラベル（「目覚まし」／「アサトモWeb」）が担い、意匠差はつけない（「アサトモ」を一つの視覚ブランドに統一）。

4. **インストール導線は誰にでも低刺激で促す**（ネイティブ所持での出し分け＝検出ゲーティングはしない。撤回の経緯は [ADR-0008 §改訂](0008-watch-web-bottom-nav-direction-split.md)）。消せるインストールバナー：iOS は「共有→ホーム画面に追加」の手動ガイド、Android は `beforeinstallprompt` の「追加する」ボタン、却下は7日クールダウンで“たまに”再提示。なふだの `usePwaInstall`／`PwaInstallBanner` を移植する。

## 結果（Consequences）

**正**

- iPhone [[本人]]・純Web [[見守り者]]がホーム画面から一発で見守りWebに戻れる。[[相互見守り]]を標準経路にした（[ADR-0004](0004-product-layering-daily-first.md)）エンゲージメントを助ける。
- **安全網の誤提示ハザードを構造的に避ける。** [[近況]]をキャッシュしないので、圏外で数時間前の「元気に過ごしています」を“今”として見せる事故が起きない。CONTEXT.md の近況設計（過去形＋経過時間で異常を測る）を、キャッシュが経過時間を凍らせて裏切ることがない。[ADR-0009](0009-alarm-silent-warning-detection-boundary.md) と同種の「沈黙を安心と誤読させない」原則を PWA 層でも守る。
- 認証済みページを SW に残さないので、ログアウト後・共有端末での残渣リスクがない。
- SW が最小なので、キャッシュ由来の「古いJSが張り付いて更新が反映されない」PWA 定番のバグを避けやすい。

**負 / 要フォロー**

- **オフラインでは何も見られない**（「接続が必要」表示のみ）。見守りWeb は本来ネット前提の面（ADR-0006）なので許容だが、将来「本人が自分の透明性画面だけ圏外で見たい」等の要望が出たら、**本人自身の非危険データに限って**慎重に再検討する余地を残す（他人の[[近況]]・危険フローには広げない）。
- ネイティブ目覚ましと同一意匠のため、両方をインストールした人（相互見守りの Android 本人など）のホーム画面ではアイコンが同じ絵で並ぶ。区別はラベル頼み。実地で紛らわしければ意匠差を後から検討（ただし決定3の統一方針を覆す判断として扱う）。

## 検討した代替案（Alternatives considered）

- **(Y) オフライン動作まで（SW でシェル・データをキャッシュ）**: 圏外でも過去画面が見えるが、[[近況]]の古い状態を“今”として誤提示し、安全網を壊す。危険フローはそもそもネット必須でキャッシュに意味がない。却下。中核的な却下理由が本 ADR の主眼。
- **PWA 化しない（ブラウザのブックマーク運用）**: 実装ゼロだが、ホーム一発復帰が無くエンゲージメントに劣る。iPhone [[本人]]には日常の入口がタブに埋もれる。却下。
- **ネイティブ所持を検出してインストール導線を出し分け**: Web からネイティブ所持は判定不能で強制できず、「アサトモWeb」改名で混同懸念も解消済み。検出機構は過剰。誰にでも低刺激で促す方式に置換（[ADR-0008 §改訂](0008-watch-web-bottom-nav-direction-split.md)）。却下。
- **アイコンを Web 用に差別化**: ラベルで既に識別でき、2意匠の保守は overhead。「アサトモ」視覚ブランドの統一を優先し却下。
